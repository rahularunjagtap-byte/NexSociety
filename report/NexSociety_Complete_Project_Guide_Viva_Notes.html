1. Executive Overview & Problem Statement

Traditional residential societies face security loopholes (paper visitor registers, manual phone calls for guest verification, unrecorded deliveries), delayed maintenance fee collection, and zero visual oversight of campus assets.

NexSociety solves this by interconnecting three key society stakeholders onto a single unified real-time cloud platform:

  • Security Guards: Instant 1-tap fast pass for delivery partners (Zomato/Swiggy), visitor registration, and OTP-driven boom barrier automation.
  • Society Residents: Pre-approve guests with 6-digit entry PINs, raise helpdesk repair tickets, track maintenance dues, and access Gate 1 intercom.
  • Executive Secretary / Admin: Real-time oversight of flat occupancy, maintenance collection audit, directory search, and broadcast circulars.
  • 3D Digital Twin HUD: Real-time WebGL interactive 3D model of Towers A, B, and C with live occupancy telemetry and parking bay status.

2. Complete System Architecture & Data Flow

Tri-Tier Resilience Architecture: The application connects to a Node.js/Express REST backend with PostgreSQL. If the backend server is offline or experiencing network drops during presentation, an automatic client-side fallback routes data to Firebase Realtime Database and LocalStorage without any crashes.

4. Backend Engineering (Node.js + Express + PostgreSQL)

The backend directory server/ handles server-side business logic, security middleware, and database operations.

A. Server Configuration (server/server.js)

  • Port: Runs on http://localhost:5000.
  • CORS & PNA Headers: Configured with Access-Control-Allow-Origin: * and Access-Control-Allow-Private-Network: true, allowing frontend instances hosted on Netlify to query the local Express server.
  • Health Endpoint: GET /api/health checks PostgreSQL connectivity and returns database status.

5. Core Feature Workflows (How It Works)

Workflow 1: 6-Digit Gate Pass Verification

  1. Generation: In Resident Portal (resident.js), resident inputs guest name and flat. A random 6-digit numeric PIN is generated (e.g. 482910) and saved to preapproved_passes.
  2. Arrival: Guest arrives at Gate 1. Guard clicks "Verify Passcode" on the Security Terminal (security.js) and inputs 482910.
  3. Verification: The system queries the database. If valid, the pass status updates from active to used, boom barrier opens, and the visitor is automatically added to the live campus log with status inside.

Workflow 2: Fintech Maintenance Payment & Receipt

  1. Resident views pending maintenance (₹4,250) on resident.html and clicks "Pay Now", redirecting to payment.html.
  2. Resident chooses payment mode: 1-Tap UPI (GPay/PhonePe) or Credit Card.
  3. Submitting payment triggers processPayment() in payment.js. It validates card/VPA inputs, simulates a 2-second bank authorization gateway, generates a unique transaction reference (e.g., TXN-NEX-88219), marks dues as PAID, and generates a GST-compliant tax receipt.

Workflow 3: 3D Digital Twin Visualizer (Three.js)

  1. twin.js initializes a WebGL scene with shadow mapping and perspective camera.
  2. Renders 3 towers: Tower A (12 floors), Tower B (10 floors), Tower C (8 floors) with distinct textures.
  3. Adds campus elements: boundary walls, boom barriers, parking bay meshes, and landscaping.
  4. A THREE.Raycaster listens to user pointer clicks. When a user clicks Tower A, it calculates intersection points, highlights the building, and slides open the telemetry HUD showing occupancy (96/120 flats occupied).

6. Frequently Asked Viva Questions & Model Answers

Q1: What is the overall architecture of NexSociety?
Answer: "NexSociety follows a modular 3-tier client-server architecture. The frontend is built using semantic HTML5, CSS3, ES6 JavaScript, and Three.js for 3D visualization. The backend is an asynchronous REST API built with Node.js and Express.js, connected to a PostgreSQL relational database. For cloud deployment and real-time cross-device monitoring, we use Firebase Realtime Database and Netlify Edge CDN."
Q2: Why did you choose PostgreSQL over MongoDB?
Answer: "Residential society management involves financial transactions (maintenance dues) and structured relational associations (visitors linked to flat numbers, complaints linked to towers). PostgreSQL guarantees ACID compliance, strict foreign key constraints, and numeric precision for financial ledgers, preventing dirty reads or lost updates."
Q3: How does your application handle network interruptions during a demo?
Answer: "We implemented a dual-mode offline-resilient architecture in api.js and script.js. If the local Express backend (port 5000) is unreachable, the frontend seamlessly falls back to LocalStorage and Firebase Realtime Database. The UI never crashes or displays broken errors."
Q4: How did you ensure responsive mobile screen fitting without horizontal scroll?
Answer: "We applied strict global viewport bounds: html, body { width: 100%; max-width: 100vw; overflow-x: hidden; }. Wide multi-column tables are wrapped in .table-responsive containers with overflow-x: auto and touch momentum scrolling. Media queries at 768px and 480px dynamically convert multi-column grids into single-column responsive layouts."
Q5: How does the 3D Digital Twin work under the hood?
Answer: "The 3D Digital Twin uses the Three.js library over WebGL. It sets up a scene, camera, ambient and directional lights, and renders procedural 3D box geometries for towers and parking lots. User click interactions are detected using THREE.Raycaster, which projects a ray from the camera through the mouse coordinates to identify clicked building meshes."
